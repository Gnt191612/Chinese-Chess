# 社区经验贡献

欢迎自愿贡献经验。没有自动上传、自动合并或在线学习；当前以GitHub Issue附件接收候选数据。程序内的安全导出／导入和社区合并工具仍为后续计划。

## 如何提交

1. 关闭程序后复制自己的 `experience.dat`，保留原文件，不直接改写。
2. 确认愿意公开：文件主要包含局面哈希、着法坐标和胜负计数，没有完整棋盘与姓名字段，但仍应视为个人行为数据。
3. 将这一个文件压缩为ZIP，使用“经验库贡献”Issue模板附上。不要附带缓存、旧局恢复文件、学校配置、账号、令牌或未经许可的棋谱。
4. 说明程序版本、是否改过记录逻辑、正常对局的大致数量、来源、可否用于公开分发和模型研究。只有自己产生或获准贡献的数据才能提交。

公开Issue附件对所有人可见；不同意公开时不要上传。若平台不接受附件或文件过大，请先提交不含数据的说明，与维护者协商，不上传到不明第三方网盘。

## 维护者审查

- 隔离保存原始附件，记录SHA-256、来源和贡献许可；不运行附件内的程序或脚本。
- 检查格式、大小、记录边界、坐标、异常计数与重复贡献，去重不能简单累加同一文件的计数。
- 当前哈希经验格式不含完整棋盘和对局历史，单凭文件不能证明着法合法、胜负正确或不存在演示污染。来源不明、修改版、无法验证的记录暂不进入发布库；未来规范化对局导出应增加验证依据。
- 最新正常记录路径会排除演示和禁用学习对局，但不据此自动信任旧库或外部文件。
- 合并候选须在相同思考预算下对照测试战术、胜率、耗时与重复率；记录越多不保证越强。

原始投稿不直接提交Git主分支，`experience.dat`仍被忽略，以保护用户数据并防止误打包。经审查的数据将独立版本化并说明来源，不覆盖用户已有本地经验。当前尚无自动合并器或已发布社区经验版本。

## 贡献者与批次追溯

每次投稿分配独立批次编号，不覆盖旧批次。目录结构采用 `community-experience/contributors/<公开标识>/<批次编号>/manifest.json`；模板见该目录README。原始文件隔离放在维护者本地 `community-experience/incoming/`，不进入Git。只有得到公开许可且通过审核的批次元数据才进入版本控制；初始目录没有真实用户投稿。

批次状态依次为 `pending`（待审）、`accepted`（通过）、`rejected`（拒收）或 `revoked`（撤销）。记录原始文件SHA-256、来源Issue、许可、审核依据、包含该批次的库版本和撤销原因。聚合库必须有输入批次清单；同一局面来自多个批次时也保留批次来源，不只保留合并后的计数。

发现污染或许可问题，先停止分发受影响版本、隔离并撤销该批次，然后从其他通过的批次重新生成并复测候选库，不能盲目从聚合计数中相减。投稿者补交数据时使用新批次编号，不替换被撤销文件。退回指通知拒收或撤销，不代表能收回公开附件与他人下载副本。

库更新公告放在 `community-experience/announcements/`，注明公开贡献标识、批次编号、受影响版本、可复现证据、修正版本及用户更新方法；参考公告模板。无证据不得把数据错误称为故意恶意污染，不公开私人身份或凭据。旧版本已被下载时不会自动消失，应通知用户升级；撤销元数据保留用于追溯，原始污染文件不作为当前有效数据继续发布。

当前只落实目录、模板和审核制度；聚合、回滚重建与客户端更新工具尚未实现，不能声称已经支持一键撤销。

## 贡献声明与使用许可

投稿者需确认对数据拥有公开和贡献的权利，并明确同意维护者存储、验证、去重，以及在来源许可允许的范围内用于经验库分发和模型研究。未作声明的投稿只用于沟通，不自动进入数据集。第三方棋谱许可与最终模型许可仍需独立确认，不能用仓库MIT许可证替代。
